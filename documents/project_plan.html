Plano do Projeto - Sistema de Gestão de Turismo

Data de entrega: 25 de Outubro de 2026

Visão Geral do Projeto

Este documento descreve o plano detalhado para o desenvolvimento de um sistema de gestão de turismo utilizando Flutter para o frontend e Oracle 10g como banco de dados backend, executado em um ambiente CentOS 6.8. O sistema permitirá gerenciamento de pacotes turísticos, reservas, clientes e relatórios.

Tecnologias Utilizadas

Flutter (Frontend) Oracle 10g (Backend Database) CentOS 6.8 (Servidor) SQL/PL/SQL (Queries e Procedures) RESTful API (Comunicação) Git (Controle de Versão)

Fases do Projeto

1

Análise e Planejamento (Semana 1-2)

Objetivo: Definir requisitos, modelar o banco de dados e estabelecer a arquitetura do sistema.

  • Reunião de levantamento de requisitos com stakeholders
  • Modelagem conceitual e lógica do banco de dados Oracle
  • Definição das APIs REST para comunicação Flutter-Oracle
  • Planejamento da estrutura de pastas do projeto Flutter
  • Configuração do ambiente de desenvolvimento (Flutter SDK, Oracle Client)
  • Criação do repositório Git inicial

Entregáveis: Documento de requisitos, modelo ER do banco, especificação da API.

2

Configuração do Ambiente e Banco de Dados (Semana 2-3)

Objetivo: Preparar o servidor CentOS com Oracle 10g e configurar a conectividade inicial.

  • Instalação e configuração do Oracle 10g no CentOS 6.8
  • Criação das tabelas conforme modelo ER definido
  • Implementação de procedures e funções PL/SQL necessárias
  • Configuração de usuários e permissões no Oracle
  • Teste de conectividade básica com SQL*Plus e SQL Developer
  • Criação de scripts de backup e recuperação inicial

Entregáveis: Banco de dados funcional, scripts de criação, documentação de configuração.

3

Desenvolvimento do Backend (Semana 3-5)

Objetivo: Criar a camada de serviço que expõe os dados do Oracle via API REST.

  • Desenvolvimento de endpoints REST para CRUD de entidades principais
  • Implementação de validações de negócio nas camadas de serviço
  • Criação de mecanismos de autenticação e autorização (se necessário)
  • Otimização de queries PL/SQL para performance
  • Implementação de tratamento de erros e logging
  • Testes unitários e de integração das APIs
  • Documentação da API (Swagger/OpenAPI ou similar)

Entregáveis: API REST funcional, testes automatizados, documentação da API.

4

Desenvolvimento do Frontend Flutter (Semana 4-7)

Objetivo: Construir a interface móvel/web consumindo as APIs desenvolvidas.

  • Criação da estrutura básica do projeto Flutter (navigation, state management)
  • Desenvolvimento de telas de autenticação (login, registro)
  • Implementação de módulos: Pacotes Turísticos, Reservas, Clientes, Relatórios
  • Integração com as APIs REST via HTTP client (dio ou http)
  • Implementação de tratamento de loading, erros e estados vazios
  • Adaptação responsiva para diferentes tamanhos de tela
  • Implementação de funcionalidades offline básicas (se necessário)
  • Testes de usabilidade e ajustes de UI/UX

Entregáveis: Aplicativo Flutter funcional conectado à API.

5

Testes, Validação e Ajustes Finais (Semana 7-8)

Objetivo: Garantir que o sistema funcione corretamente em todos os cenários e esteja pronto para entrega.

  • Testes funcionais completos (fluxos de reserva, consulta, etc.)
  • Testes de performance e carga básica
  • Validação de integridade dos dados no Oracle
  • Testes de segurança básica (injeção SQL, validação de entrada)
  • Ajustes de UI/UX baseado nos testes
  • Otimização de queries e endpoints lentos
  • Documentação final do sistema (manual do usuário, guia de instalação)
  • Preparação do pacote final para entrega

Entregáveis: Sistema testado e validado, documentação completa, código fonte final.

Configuração do Banco de Dados Oracle

  • Tablespace: Criar tablespace dedicada para o projeto
  • Usuário: Criar usuário com privilégios necessários
  • Tabelas Principais:
    • CLIENTES (id_cliente, nome, email, telefone, endereco, data_cadastro)
    • PACOTES_TURISTICOS (id_pacote, destino, preco, data_inicio, data_fim, descricao)
    • RESERVAS (id_reserva, id_cliente, id_pacote, data_reserva, status, quantidade_pessoas, valor_total)
  • Sequences: Para geração automática de IDs
  • Triggers: Para preencher campos de auditoria (se necessário)
  • Procedures: Para operações complexas de negócio
  • Views: Para relatórios e consultas frequentes

Validações e Testes

Tipos de Validação a Serem Implementados

1. Validações de Entrada (Frontend Flutter)

  • Campos obrigatórios não vazios
  • Formato de email válido
  • Formato de telefone válido
  • Valores numéricos dentro de faixas esperadas
  • Datas válidas (data de início anterior à data de fim)
  • Prevenção de XSS em campos de texto livre

2. Validações de Negócio (Backend Oracle/API)

  • Verificação de disponibilidade de pacotes nas datas solicitadas
  • Validação de crédito/limite do cliente (se aplicável)
  • Regras de negócio específicas (ex: desconto para grupos acima de X pessoas)
  • Prevenção de reservas duplicadas
  • Validação de status de reserva (cancelado, confirmado, pendente)
  • Integridade referencial entre tabelas

3. Testes a Serem Executados

  • Testes Unitários: Validação de funções e métodos individuais
  • Testes de Integração: Verificação da comunicação Flutter ↔ API ↔ Oracle
  • Testes de Sistema: Fluxos completos de uso (busca pacote → faz reserva → confirma pagamento)
  • Testes de Performance: Tempo de resposta das APIs sob carga moderada
  • Testes de Segurança: Tentativas de injeção SQL, acesso não autorizado
  • Testes de Usabilidade: Feedback de usuários reais sobre a interface

Critérios de Aceitação para Entrega

  • ✅ Sistema capaz de realizar CRUD completo em todas as entidades principais
  • ✅ Interface Flutter responsiva e funcional em pelo menos uma plataforma (Android/iOS/Web)
  • ✅ Banco de dados Oracle 10g corretamente populado e funcionando no CentOS 6.8
  • ✅ API REST funcional com documentação básica
  • ✅ Todas as validações de entrada e negócio implementadas
  • ✅ Sistema livre de bugs críticos que impeçam o uso básico
  • ✅ Documentação final incluíndo manual do usuário e guia de instalação
  • ✅ Código fonte organizado e comentado adequadamente
  • ✅ Backup do banco de dados fornecido junto com o código fonte

Riscos Identificados e Mitigação

  • Risco: Problemas de compatibilidade entre versões do Flutter e dependências
    Mitigação: Usar versões LTS estáveis e testar em dispositivo real semanalmente
  • Risco: Complexidade na configuração do Oracle 10g no CentOS 6.8 (versão antiga)
    Mitigação: Documentar cada passo da instalação e usar imagens de máquina virtual prontas quando possível
  • Risco: Performance das queries em volumes de dados maiores
    Mitigação: Criar índices adequados e otimizar queries durante desenvolvimento
  • Risco: Falta de tempo para conclusão de todas as funcionalidades
    Mitigação: Priorizar funcionalidades essenciais (CRUD básico) e deixar avançadas para versões futuras
